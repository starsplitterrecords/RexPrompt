# visions-release

## Trigger
publish approved issue site. Do not trigger for quoted examples or non-operational discussion.

## Authority
Inspect the live relevant repository files before work. RexPrompt assembled recipes, released StarSplitterVisions canon, approved unpublished production and Keeper references are DIFFERENT authorities. Follow explicit current user instructions and approvals. Same Rex Fleet-derived workflow for every IMG series; no Division Threshold exception.

## Steps
Inspect live starsplitterrecords/StarSplitterVisions main. Publish exactly approved unchanged original asset versions to current sites/visions conventions and update series JSON, cover, release date, reading-order paths, collected PDF and site references. Runtime paths start /images or /issues. Rebuild PDF on replacement, run checks, merge and verify actual live links before calling published canon. Never publish an unapproved draft.

## Default issue cover
Use the first approved page in the curated complete-book reading order as the issue cover for new or replacement releases. Publish the exact page-one JPEG blob at the issue-specific canonical `/images/covers/` path as well as its reader path. Do not require a separate cover upload, duplicate the cover in the reading order, or alter other previously released issues. Keep released cover, homepage, and series references consistent with their established paths.

## Failure and completion
Check real files, original pixels, source identities, approval, commit/ref and end result as applicable; reject unverified claims. Report exact blockers. Preserve all previously approved work and never delete an artifact before permanent saving. Do not imply that a GitHub skill has been executed merely because its text exists, or that an image has been inspected merely because its manifest is readable.
